# TVBox 接口池 —— 每行一个, # 开头为注释
#
# 格式1: 手动接口行 (苹果CMS直链接口, 会被检测进 tvbox.json)
#   https://接口域名/api.php/provide/vod/?ac=list | 别名
#
# 格式2: 订阅行: @配置地址 | 显示名
#   - 配置本身与其子仓(含孙仓, 跟到最后一级)进入体检, 合格进 store.json
#   - 支持: 带注释JSON / 图片伪装Base64 / 中文域名
#   - v2: 同内容克隆仓(不同多仓指向同一子仓)自动去重, 只收一次
#
# 格式3: 直播上游行: L|m3u地址 | 显示名
#   - ffmpeg逐条拉流实测画质, 主线路>=720p, 备用线路>=540p
#   - 排序: 稳定优先(延迟分档>分辨率); IPv6/疑似广告拒收
#
# 格式4: 目录仓发现行: D|目录仓resources.json地址 | 显示名
#   - 自动读取目录仓里 tvbox_config 类的配置地址, 体检合格即进清单
#   - 点播源自动发现池, 无需人工添加新仓
#
# 说明: 仓或接口死了当天自动从清单消失, 活了自动回来; 无需手动维护
# 加新仓 = 加一行; 不要的删一行; 第二天自动生效(每天凌晨5点体检一轮)
#
# ---- v12: 选源标准变了, 请按两条新原则加仓 ----
# ① 优先直连域名(jar/js 和配置同域, 或七牛云/阿里云OSS这类 CDN)
#    反例: 配置和 jar 都在 raw.githubusercontent.com, 只能走 gh-proxy 中转 ——
#    实测那条通道 21KB/s, 拉一个 2.68MB 的 jar 要 130 秒, 电视上就是无限转圈。
# ② 优先 jar 打包型(csp_ 站点), 少用外挂 js 型(./lib/*.js)
#    打包型只需下 1 个 jar, 之后全在本地跑; 外挂型每开一个站都要再发请求。
# 这两条现在由脚本自动判定(GitHub依赖 > 30% 直接不收), 你不用自己算,
# 报告 report.md 里每个仓都标了 `GH依赖` 和 `jar率` 两列。
#
# 多仓会自动展开成独立子仓各自体检, 只有合格的那几个进清单 ——
# 所以一行多仓 = 几十个候选, 是扩大候选池最省事的方式。
